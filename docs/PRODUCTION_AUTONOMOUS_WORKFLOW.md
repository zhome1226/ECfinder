# Production Autonomous Workflow

Stage 2.7 upgrades the Stage 2.6 streaming workflow into a production daemon that can run until the Zotero library has no runnable sources left, subject to explicit safety budgets.

## Entry Point

```powershell
python scripts/run_production_autonomous_daemon.py `
  --library zotero `
  --mode title_abstract_to_database `
  --until-library-exhausted `
  --checkpoint-every 25 `
  --rescan-zotero-attachments-every-cycle `
  --max-wall-minutes 120 `
  --max-new-screen 300 `
  --max-new-fulltext 80 `
  --max-new-extract-sources 40 `
  --safe-stop-on-token-budget `
  --token-budget 250000
```

The limits are safety budgets. They do not change the daemon model: each cycle discovers runnable sources, chooses the next source, completes that source's current workflow cycle, writes state, and then decides whether to continue.

## Source Lifecycle

Each source is classified as one of:

- `completed`: validated, rejected, auxiliary, completed_no_records, or excluded.
- `manual_screen`: title/abstract or boundary ambiguity requiring human decision.
- `blocked_external`: include_for_fulltext but no lawful local PDF/HTML attachment is available.
- `deferred`: runnable but held by a configured safety limit.
- `runnable_screening`: not yet screened.
- `runnable_fulltext`: already included for full text and local full text is available.
- `runnable_parse`, `runnable_extraction`, `runnable_review`, `runnable_database_write`: resumable in-progress states.

Blocked sources do not stop the daemon. They are rescanned on later cycles, and if a local Zotero attachment appears they become runnable again.

## Streaming Chain

For every runnable source the daemon preserves the closed loop:

```text
TitleAbstractScreeningAgent
-> FulltextAvailabilityAgent / ZoteroAttachmentAgent
-> ParseChunkAgent
-> ChunkRelevanceAgent
-> ExtractionAgent
-> ReviewAgent
-> DatabaseWriteAgent
```

Title/abstract screening receives only `source_id`, `doi`, `title`, `abstract`, `year`, `journal`, and `keywords`. It never receives PDF paths, full text, chunks, or the full library. Parse/chunk is deterministic and does not call an LLM. Extraction receives only chunks that passed relevance screening. Every candidate generated by extraction is reviewed immediately and written immediately to one of validated, manual review, rejected, or auxiliary outputs.

## Output Contract

Stage 2.7 batch outputs are written to:

- `data/batches/stage2_7_screening_decisions.jsonl`
- `data/batches/stage2_7_chunk_screening.jsonl`
- `data/batches/stage2_7_candidate_records.jsonl`
- `data/batches/stage2_7_reviewed_records.jsonl`
- `data/batches/stage2_7_validated_records.jsonl`
- `data/batches/stage2_7_manual_review_records.jsonl`
- `data/batches/stage2_7_rejected_records.jsonl`
- `data/batches/stage2_7_auxiliary_records.jsonl`

Daemon state is written to:

- `data/state/stage2_7_library_source_status.jsonl`
- `data/state/stage2_7_daemon_events.jsonl`
- `data/state/stage2_7_daemon_checkpoint.json`
- `data/state/stage2_7_blocked_external_queue.jsonl`
- `data/state/stage2_7_manual_screen_queue.jsonl`
- `data/state/stage2_7_deferred_queue.jsonl`
- `data/state/stage2_7_completed_sources.jsonl`

All JSONL files must be one physical JSON object per line, written with `json.dumps(record, ensure_ascii=False, sort_keys=True) + "\n"` after recursive string normalization. Parsed strings must not contain raw CR/LF characters, and no line may contain `} {`.

## Checkpoint And Resume

The daemon writes `data/state/stage2_7_daemon_checkpoint.json` every configured checkpoint interval and once at safe stop. Resume mode reads Stage 2.6c/d/e/f state plus Stage 2.7 state:

```powershell
python scripts/run_production_autonomous_daemon.py `
  --library zotero `
  --mode title_abstract_to_database `
  --resume `
  --until-library-exhausted
```

Resume must not repeat completed or excluded sources. A previously blocked source can be processed only if a rescan finds an available PDF/HTML attachment.

## Safe Stop

Safe stop is checked only between complete source cycles. A candidate is never left unreviewed. Supported stop conditions are:

- `--max-wall-minutes`
- `--max-records`
- `--max-new-screen`
- `--max-new-fulltext`
- `--max-new-extract-sources`
- `--safe-stop-on-token-budget --token-budget`
- `--stop-file`, defaulting to `data/state/STOP_DAEMON`

## Validation

Run the Stage 2.7 validator and the retained Stage 2.6 validators before scaling:

```powershell
python scripts/validate_stage2_7_production_daemon.py
python scripts/validate_stage2_6f_environment_priority_streaming.py
python scripts/validate_stage2_6e_attachment_priority_streaming.py
python scripts/validate_stage2_6d_streaming_workflow.py
python scripts/validate_stage2_6c_streaming_workflow.py
```

Do not commit PDFs, publisher HTML, Zotero storage copies, SI files, or local repair notes.
